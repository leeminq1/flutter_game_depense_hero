# 전투 UX·조작형 튜토리얼·Stage 1 비주얼 수직 슬라이스 설계

- 상태: 사용자 방향 승인 완료, 서면 검토 대기
- 작성일: 2026-08-09
- 대상: Android 우선 Flutter + Flame 게임 `PIXEL GUARD: WAVE`
- 검증 게이트: 구현 완료 후 사용자가 실기기에서 직접 평가하고, 승인 전까지 Stage 2~30으로 확장하지 않는다.

## 1. 결정 요약

이번 작업은 게임 난이도와 전투 밸런스를 유지하면서 전투 UX와 첫 플레이 이해도를 개선하는 1차 리뉴얼이다.

승인된 방향은 다음과 같다.

1. 하단 건설 패널은 `상태 적응형 컴팩트` 구조로 바꾼다.
2. 건설 카드는 `74×82` 논리 픽셀 균형형을 사용한다.
3. 확대·이동·원위치 복귀를 발견하기 쉽고 충돌 없이 동작하도록 보완한다.
4. 일시정지 상태에서는 버튼이 재생 아이콘과 `재개` 의미로 즉시 바뀐다.
5. 기존 Stage 1 설명 팝업을 제거하고 2~3분짜리 전용 훈련맵을 추가한다.
6. 훈련맵에서 출현 방향, 성벽 차단, 타워 통과·접촉 피해, 안전 배치와 조합 방어를 실제 조작으로 학습한다.
7. 맵 아트는 `엔진 제약형 B: 탑다운 3/4 픽셀`을 Stage 1 수직 슬라이스로 검증한다.
8. 사용자의 실기기 승인 전에는 나머지 Stage와 전체 로스터 아트를 교체하지 않는다.

## 2. 범위

### 포함

- 메인 메뉴의 독립 `튜토리얼` 진입 버튼
- 새 게임 → 훈련맵 → Stage 1 흐름
- 메뉴에서 튜토리얼만 재실행했을 때의 완료 선택 팝업
- 기존 Stage 1 팝업 튜토리얼 제거
- Stage 1의 짧은 비차단형 복습 안내
- 준비/전투 상태에 따라 달라지는 하단 패널
- 74×82 건설 카드와 축소된 내부 간격
- 초점 고정 핀치 줌, 드래그 이동, 카메라 원위치 버튼
- 명확한 일시정지/재개 상태
- 방향 마커의 북·남·동·서 표기와 현재/다음 Wave 구분
- 바닥 피벗, 논리 점유칸, Y축 정렬, 연결 성벽 렌더링
- Stage 1용 지면·길·성채·소품과 T1 타워/성벽 비주얼 검증 세트
- 관련 단위·위젯·통합 테스트와 실기기 점검표

### 제외

- 적 체력, 이동 속도, 공격력, 보상, Wave 구성 변경
- 타워·성벽의 비용, 사거리, 피해량, 내구도 변경
- 캠페인 진행·별·메타 업그레이드 규칙 변경
- Stage 2~30 비주얼 전체 교체
- 모든 T2/T3/분기 타워의 B 스타일 완성
- 영웅·적 전체 재작업
- 사운드, 광고, 과금 또는 신규 콘텐츠 추가

훈련 자동 시범의 `1.5배속`은 튜토리얼 내부 연출에만 적용하며 실제 Stage의 적 이동 속도에는 영향을 주지 않는다.

## 3. 전투 화면 UX

### 3.1 하단 패널

준비/회복 상태의 패널 목표 높이는 약 150~175 논리 픽셀이다.

- 상단의 긴 2줄 설명은 제거하고 한 줄 상태 안내로 바꾼다.
- 탭, 카드, Wave 버튼을 한 덩어리로 압축한다.
- 카드 크기는 74×82로 고정한다.
- 카드 아이콘은 약 22px, 이름은 약 11.5px, 비용은 약 11px을 기준으로 한다.
- 아이콘–이름 간격은 4px, 이름–비용 간격은 2px을 기준으로 한다.
- 카드 전체가 터치 영역이므로 최소 터치 크기를 만족한다.
- 선택 카드의 상세 정보는 패널 높이를 늘리지 않고 전장 위 작은 플로팅 정보 영역에서 보여준다.

Wave 진행 중에는 건설이 불가능하므로 카드와 탭을 접고 약 52~60px의 전투 바만 남긴다. 전투 바에는 Wave 상태만 제공하며 건설 카드를 수동으로 펼치지 않는다. Wave 종료 후 준비 상태가 되면 패널을 자동 복원한다. 배치된 타워 정보는 전장의 타워를 직접 탭해 확인한다.

### 3.2 카메라

- 실기기 보정 후 줌 범위는 `1.0~2.5`로 사용한다. 1.0배가 14×14 전장의 기본 맞춤 상태다.
- 핀치 중심에 있던 전장 위치가 화면에서 움직이지 않도록 초점 고정 줌을 적용한다.
- 한 손가락 이동이 터치 슬롭 8px을 넘으면 카메라 드래그로 처리하고, 그 이하면 기존 탭/배치로 처리한다.
- 건설 카드가 선택되어 있어도 드래그 후 손을 떼는 동작은 건설로 오인하지 않는다.
- 전장이 화면 밖으로 완전히 사라지지 않도록 이동 범위를 제한한다.
- 기본 위치와 다를 때만 작은 `원위치` 버튼을 보여주고, 누르면 기본 카메라로 짧게 복귀한다.

훈련 초반에 확대·이동을 직접 시도하는 짧은 단계가 있지만 5초 후 `건너뛰기`를 제공하여 진행을 막지 않는다.

### 3.3 일시정지

- 실행 중 버튼은 `Ⅱ`, 일시정지 중 버튼은 `▶`로 표시한다.
- 일시정지 오버레이의 주 동작은 `▶ 재개`이다.
- 일시정지 중에는 시뮬레이션, 적 이동, 타워 공격, 튜토리얼 자동 시범 시간이 모두 멈춘다.
- 재개하면 버튼과 오버레이가 같은 프레임에 정상 상태로 복귀한다.

## 4. 튜토리얼 경험

### 4.1 진입과 종료

#### 새 게임

`새 게임`은 항상 훈련맵으로 진입한다. 이미 튜토리얼을 완료한 사용자에게는 첫 화면부터 `건너뛰고 Stage 1` 동작을 제공한다.

훈련을 완료하거나 완료 이력이 있는 사용자가 `건너뛰고 Stage 1`을 선택하면 별도의 선택 팝업 없이 Stage 1을 시작한다. 두 경우 모두 Stage 1에서는 기존 팝업 대신 핵심 규칙 두 개만 짧은 스포트라이트 안내로 복습한다. `이어하기`로 Stage 1에 복귀할 때는 이 복습을 다시 표시하지 않는다.

#### 메인 메뉴의 튜토리얼

메인 메뉴에 `튜토리얼` 버튼을 독립 항목으로 배치한다. 이 경로는 캠페인 진행, 보상, 통계를 변경하지 않는다.

완료 시 다음 두 선택을 제공한다.

- `다시 보기`: 훈련맵을 초기 상태로 재시작
- `홈 화면`: 메인 메뉴로 복귀

### 4.2 단계 구성

목표 시간은 2~3분이며 실패로 막히는 단계는 없다.

1. **전장 둘러보기**
   - 핀치 확대와 드래그 이동을 직접 시도한다.
   - 5초 후 건너뛰기 가능하다.
2. **출현 방향 읽기**
   - 북·남·동·서 마커와 길, 성채를 스포트라이트로 보여준다.
   - `다음 WAVE: 북·서`처럼 HUD에도 글자로 표시한다.
   - 현재 출현 방향은 선명한 고정/펄스, 다음 방향은 반투명 점선으로 구분한다.
3. **성벽으로 길 막기**
   - 지정 셀에 성벽을 실제로 배치해야 진행된다.
   - 적 이동 경로가 성벽 앞에서 멈추는 이유를 설명한다.
4. **초록 땅의 안전한 타워 배치**
   - 초록 땅에 타워를 직접 배치한다.
   - 사거리와 길을 동시에 보여주며 길 밖에서도 공격할 수 있음을 확인한다.
5. **위험한 배치 자동 비교**
   - 플레이어의 자원이나 진행을 소모하지 않는 시범 전용 타워와 적을 사용한다.
   - 적은 튜토리얼 시뮬레이션 안에서만 1.5배속으로 움직인다.
   - 문구: `타워만으로는 몬스터를 막지 못합니다. 몬스터가 통과하면서 종류별 접촉 피해를 줍니다.`
   - 타워 체력 감소를 짧은 숫자와 체력 바로 동시에 보여준다.
6. **성벽 뒤 타워 조합**
   - 길 위 성벽 뒤 또는 길 옆 안전 지형에 타워를 배치한다.
   - 성벽은 이동을 막고 타워는 뒤에서 공격하는 역할 차이를 강조한다.
7. **미니 Wave**
   - 플레이어가 직접 Wave를 시작한다.
   - 첫 일시정지 사용 시 `▶ 재개` 상태를 짧게 안내하되 강제하지 않는다.
8. **완료 요약**
   - 출현 방향, 성벽 차단, 타워 통과, 조합 방어를 체크리스트로 확인한다.
   - 진입 경로에 따라 Stage 1 또는 완료 선택 팝업으로 이동한다.

### 4.3 튜토리얼 구조

튜토리얼은 일반 Stage의 전투 수치를 변경하지 않는 별도 훈련 세션으로 구성한다.

- `TutorialStageDefinition`: 보상과 캠페인 번호가 없는 14×14 전용 맵
- `TutorialDirector`: 현재 단계, 허용 동작, 완료 조건, 자동 시범을 관리
- `TutorialSnapshot`: Flame 상태를 Flutter 오버레이에 읽기 전용으로 전달
- `TutorialOverlay`: 투명 스크림, 스포트라이트, 콜아웃과 단계 버튼을 표시
- `TutorialProgress`: 완료 여부만 영구 저장

Flutter는 메뉴·오버레이·완료 팝업을 소유하고 Flame은 배치·시범 적·전투 상태를 소유한다. 오버레이는 현재 학습 대상만 터치가 통과되도록 하되 시스템 뒤로가기와 튜토리얼 종료는 항상 가능해야 한다.

기존 Stage 1 팝업은 단순히 완료 플래그로 숨기는 방식이 아니라 호출 경로 자체를 제거한다.

## 5. 엔진 제약형 B 비주얼

### 5.1 목표와 제한

목표는 처음 생성한 B 콘셉트의 색감, 재질, 픽셀 밀도와 통일감을 현재의 자유 배치 규칙 안에서 재현하는 것이다.

다음 요소는 사용하지 않는다.

- 미리 완성된 장거리 성벽이나 성문 장면
- 대각선/곡선 자유형 성벽
- 전체 맵을 둘러싼 고밀도 절벽과 숲
- 점유칸보다 넓은 충돌 판정
- 배경에 타워 위치가 미리 그려진 맵 이미지

### 5.2 렌더링 메타데이터

기존 `UnitVisualDefinition`을 직접 비대하게 만들지 않고 공통 구조물 렌더 메타데이터를 둔다.

- 에셋 경로
- 원본 픽셀 크기
- 논리 점유칸 크기
- 바닥 중심 피벗
- 타일 기준 렌더 크기
- 추가 오프셋
- 기본 Z 레이어
- 그림자 규칙

타워는 128×128 PNG를 기본 원본으로 사용하고 한 칸 바닥 피벗에 고정한다. 성벽과 지면 타일은 64×64를 사용한다. 2×2 성채는 256×256 이내의 원본으로 정리한다. 렌더링은 원본 종횡비를 유지하고 정사각형 강제 왜곡을 하지 않는다.

### 5.3 연결 성벽

각 성벽은 기존과 동일하게 한 칸씩 배치되고 기존 HP와 경로 차단 규칙을 사용한다. 비주얼만 인접한 상·우·하·좌 성벽을 4비트 마스크로 계산한다.

마스크에 따라 다음 모양을 선택한다.

- 고립
- 상/우/하/좌 끝
- 가로/세로 직선
- 네 방향 모서리
- 네 방향 T자
- 십자

네 성벽 재질은 동일한 연결 규칙을 공유한다. 변형은 AI가 64장을 독립적으로 생성하지 않고, 승인된 재질별 모듈 원본에서 결정론적으로 조합해 시점과 연결 위치가 흔들리지 않게 만든다.

### 5.4 Y축 정렬

바닥과 배경 장식 이후, 다음 요소를 공통 `RenderItem` 목록으로 모은다.

- 성벽
- 타워
- 성채와 전경 장애물
- 영웅과 병영 수비대
- 적

기본 Z 레이어와 바닥 피벗의 Y값으로 정렬한다. 투사체, 범위, 피해 숫자와 튜토리얼 강조 표시는 기존 가독성 우선 레이어에 남긴다.

### 5.5 Stage 1 수직 슬라이스 에셋

실기기 판단에 필요한 최소 세트만 먼저 제작한다.

- 잔디 기본/변형 타일
- 직선·모서리·끝을 포함한 흙길 타일
- 네 성벽 재질의 연결 모듈
- 7개 타워 계열의 T1 비주얼
- 훈련과 Stage 1의 성채
- 우물, 수레, 표지판, 울타리, 바위, 관목, 소형 주택 등 저밀도 소품
- 북·남·동·서 출현 마커

T2/T3와 분기 타워는 이 단계에서 기존 비주얼을 폴백으로 유지한다. 실기기 승인 후 확장 단계에서 B 스타일로 교체한다. Stage 1에서 업그레이드 비주얼을 확인할 때 기존 폴백이 사용된다는 점은 수직 슬라이스 테스트 안내에 명시한다.

AI 생성 에셋은 최종 사용 전에 투명 배경, 피벗, 크기, 팔레트, 연결선, 라이선스와 출처를 검수한다. 사용한 프롬프트, 생성 원본, 후처리 방식과 내보내기 규격을 `docs/generated/`에 기록한다.

## 6. 데이터 흐름과 경계

### 전투 UX

Flame 게임은 카메라 변환과 전투 상태를 소유한다. Flutter 화면은 읽기 전용 세션 스냅샷을 받아 하단 패널 상태와 버튼을 렌더링한다. 패널 상태를 추론하기 위해 가변 전투 리스트를 직접 읽지 않는다.

### 튜토리얼

`TutorialDirector`가 Flame의 승인된 이벤트를 받아 단계 완료 여부를 결정하고 `TutorialSnapshot`을 갱신한다. Flutter 오버레이는 스냅샷에 선언된 문구, 강조 영역과 허용 동작만 표시한다.

### 비주얼

전투 판정은 기존 월드 좌표와 점유 셀을 계속 사용한다. 렌더 피벗과 이미지 높이는 충돌·사거리·경로 계산에 영향을 주지 않는다.

## 7. 실패 처리와 복귀

- 튜토리얼 자동 시범 적이 예상 경로를 벗어나면 시범 상태만 초기화하고 사용자의 진행은 유지한다.
- 필요한 튜토리얼 에셋을 불러오지 못하면 기존 도형/스프라이트 폴백으로 진행 가능해야 한다.
- 앱이 튜토리얼 중 백그라운드로 가면 일시정지하고 복귀 시 같은 단계에서 재개한다.
- 튜토리얼 중 홈으로 나가면 일반 캠페인 진행은 변경하지 않는다.
- 새 렌더 메타데이터가 없는 기존 에셋은 현재 중앙 기준 렌더링 규칙으로 폴백한다.

### 실기기 검증

- 튜토리얼을 처음 보는 사용자가 2~3분 안에 완료 가능한가
- 성벽과 타워의 역할 차이를 설명 없이 재현할 수 있는가

- 74×82 카드가 작게 느껴지지 않는가

- Wave 중 52~60px 전투 바가 전투를 가리지 않는가
- 1배와 2.5배에서 타워·성벽·유닛이 선명하고 접지되어 보이는가
- 드래그 후 잘못된 건설이 발생하지 않는가
- 성벽 직선·모서리·T자 연결이 자연스러운가
- 앞뒤 겹침이 전투 판단을 방해하지 않는가
- 목표 기기에서 전투 중 안정적인 60FPS를 유지하는가

## 9. 완료와 확장 게이트

이번 작업의 완료는 다음을 의미한다.

1. 위 범위의 코드와 Stage 1 수직 슬라이스 에셋이 구현된다.
2. 자동 검증이 통과한다.
3. 사용자가 실기기에 연동해 실행할 수 있는 상태로 전달된다.
4. 알려진 폴백과 실기기 점검 항목을 함께 전달한다.

그 이후에는 사용자의 실기기 판단을 기다린다. 사용자가 B 방향을 승인한 경우에만 T2/T3/분기 타워, 나머지 환경 테마와 Stage 2~30으로 확장한다. 승인하지 않으면 동일한 UX 개선을 유지한 채 A급 LPC 리마스터 범위로 아트 비용을 낮춘다.

## 10. 1차 실기기 피드백 보정 (2026-08-09)

실기기에서 Stage 1 수직 슬라이스를 확인한 결과, 비주얼 완성도보다 화면 경계와 정보 가시성이 먼저 보정되어야 한다. 이번 보정은 다음 규칙으로 잠근다.

- 전장 렌더링은 상단 HUD 아래와 하단 건설 패널 위의 명시적 클립 영역 안에서만 보인다. 최대 확대에서도 시스템 SafeArea와 HUD를 덮지 않는다.
- Stage 1 기본 카메라는 1.0배로 14×14 전장을 화면 폭에 맞춘다. 1.0배보다 축소하지 못하게 하여 빈 외곽이 크게 노출되지 않게 하고, 원위치 버튼은 이 기본 상태로 돌아간다.
- 모바일 HUD는 코인과 Stage를 양끝에 고정하고 Wave·남은 적·출현 방향만 가운데에서 스크롤한다. 건설 카드를 고른 상태에서도 보유 코인이 화면 밖으로 밀리지 않는다.
- Stage 1 성벽은 현재 화면에 표시된 적 이동 길 위에서만 배치할 수 있다. 타워와 영웅은 기존처럼 유효한 초록 땅과 길 위에 배치할 수 있다. 이 규칙의 Stage 2~30 확장은 Stage 1 실기기 승인 뒤에 판단한다.
- 성벽 선택 시 길 칸만 강조하고, 타워 선택 시 전체 유효 칸은 낮은 대비로 표시해 지면보다 강하게 보이지 않게 한다.
- Stage 1 잔디 반복 텍스처의 대비를 낮춰 개별 사각 타일 경계보다 길과 구조물이 먼저 읽히게 한다.
- Stage 1 성채는 논리 점유칸을 바꾸지 않고 렌더 크기와 아래쪽 오프셋만 줄여 인접 영웅과 구조물을 가리지 않게 한다.
- Stage 1 복습 카드는 닫기 버튼을 요구하지 않고 약 3초 뒤 자동으로 사라진다.

난이도, 적 구성, Wave 수치, 비용과 전투 밸런스는 변경하지 않는다.

## 11. 2차 실기기 피드백 보정 (2026-08-09)

이 절은 앞부분의 `상태 적응형 컴팩트 전투 바`, `1.0배 상단 고정 Stage 1`, `연결 성벽`, `T1 전용 수직 슬라이스` 결정을 대체한다. 전투 수치와 업그레이드 기능은 그대로 두고 화면 안정성과 Stage 1 아트 일관성을 보정한다.

### 11.1 튜토리얼 안내 위치

- `TutorialOverlay`는 전체 화면 Stack이 아니라 HUD와 하단 패널 사이의 전장 Stack 안에 둔다.
- 1~5단계의 안내 카드는 모두 전장 하단 중앙에 정렬한다.
- 안내 카드는 상단 HUD를 덮지 않으며, 하단 튜토리얼 건설 패널도 덮지 않는다.
- 카메라 조작용 투명 가이드와 실제 조작 입력은 유지한다.
- 완료 버튼과 건너뛰기 버튼의 동작은 변경하지 않는다.

### 11.2 준비·전투 공통 하단 패널

- WAVE 시작 시 건설 패널을 56px 전투 바로 교체하지 않는다.
- 준비 상태에서 사용하던 탭, 74×82 카드 행, 하단 액션 버튼 구조를 전투 중에도 그대로 유지한다.
- 전투 중 탭과 카드는 보이되 비활성화한다. 전투 중 신규 건설은 계속 금지한다.
- 준비 상태의 하단 버튼은 `WAVE 시작`, 전투 상태에서는 `일시정지/재개`로만 바뀐다.
- 같은 위젯 구조와 높이를 유지하여 WAVE 전환 때 `GameWidget`의 크기와 월드 원점이 바뀌지 않게 한다.

### 11.3 Stage 1 기본 카메라

- 안정된 전장 영역 안에서 14×14 맵의 중심이 화면 중심과 일치하도록 수직 중앙 정렬을 복구한다.
- Stage 1 기본 카메라는 중앙 기준 약 1.1배 확대 상태로 시작한다.
- 사용자가 이동·확대·축소한 뒤 `원위치`를 누르면 1.0배가 아니라 이 Stage 1 기본 상태로 돌아간다.
- 기본 1.1배 상태에서는 원위치 버튼을 표시하지 않는다.
- WAVE 시작과 패널 버튼 상태 변경은 카메라 스냅샷을 초기화하지 않는다.

### 11.4 Stage 1 타워 T2·T3 리뉴얼

기존 업그레이드 수치, 레벨 전이, 분기 선택과 전투 기능은 변경하지 않는다. Stage 1의 새 T1 이미지와 예전 T2·T3 이미지가 섞이는 렌더링만 교체한다.

- 대상은 궁수, 병영, 마법사, 빙결, 금화 방앗간, 발리스타, 엠버킵 7종이다.
- 각 타워에 새 T2와 T3를 제작하여 총 14개 PNG를 추가한다.
- 파일명은 `assets/sprites/stage1/towers/<tower>_t2.png`, `<tower>_t3.png` 규칙을 사용한다.
- 새 T2·T3는 해당 Stage 1 T1을 시점·팔레트·바닥 피벗 기준으로 사용하고, 기존 일반 타워 T2·T3는 구조적 성장 요소 참고용으로만 사용한다.
- T2는 T1 실루엣을 유지하면서 방어판, 층고, 장식과 무장 밀도를 한 단계 높인다.
- T3는 동일 건물임이 읽히는 범위에서 가장 강한 실루엣과 재질 강조를 사용한다.
- 투명 배경, 동일한 탑다운 3/4 시점, 일관된 광원, 픽셀 경계와 한 칸 바닥 피벗을 유지한다.
- Stage 1 렌더러는 `tower(kind, level)`로 T1~T3를 선택하고, 레벨 4는 T3를 재사용한다.
- Stage 1에서는 분기별 옛 이미지로 되돌아가지 않고 새 T2·T3 공통 외형을 우선한다. 분기 기능과 수치는 그대로 유지된다.

기존 `assets/sprites/towers/` 자산은 Stage 2~30과 분기 외형 폴백이 사용하므로 일괄 삭제하지 않는다. 코드·카탈로그·테스트·에셋 매니페스트 전체 참조 검사에서 사용되지 않는 것으로 확인된 파일만 삭제한다. 새 자산의 프롬프트, 참조 파일, 생성일과 용도는 `docs/generated/`에 기록한다.

### 11.5 검증 기준

- 튜토리얼 1~5 안내 카드가 모두 전장 하단에 있고 HUD가 보인다.
- 준비와 전투 중 하단 패널 높이가 같다.
- 전투 중 카드가 보이지만 건설 입력은 비활성화된다.
- WAVE 시작 전후 전장 viewport 크기, 맵 중심과 설치 셀이 변하지 않는다.
- Stage 1 기본 카메라와 원위치가 같은 중앙 1.1배 상태를 사용한다.
- 7종 타워 모두 레벨 1·2·3에서 서로 다른 Stage 1 자산 경로를 사용한다.
- 레벨 4와 분기 업그레이드의 전투 기능은 기존 테스트를 그대로 통과한다.
- 기존 자산 삭제 전 참조 검사를 수행하며 Stage 2~30 폴백을 깨뜨리지 않는다.
- 관련 위젯·카메라·비주얼 카탈로그 테스트, `flutter analyze`, Debug APK 빌드와 실기기 설치를 수행한다.
